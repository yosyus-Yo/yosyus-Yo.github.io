## 에이전트 플랫폼

- **구독형 모델 공급자 추가**: 의사결정 평가가 API 키 호출뿐 아니라 CLI 로그인 기반 구독 모델(Codex 등)로도 판정하도록 공급자를 붙였다. 구독 호출은 예산 예약을 0으로 처리하고, 토큰 초과 방지와 설정 검증을 넣었다. 독립 검토에서 토큰 예산 강제의 빈틈이 지적돼 같이 막았다.
- **큰 프롬프트가 막히는 문제**: CLI 공급자가 표준 입력 파이프로 긴 프롬프트를 넘기다 버퍼가 가득 차 멈추던 문제를 고쳤다. 프롬프트를 파일로 전달하는 경로를 추가했다.
- **UI 폴링 정리**: 협업 기능이 꺼진 서버에서는 빈 화면 대신 안내를 보여주고, 존재하지 않는 경로를 계속 다시 조회하던 루프를 끊었다.
- **API 문서 생성기**: 업무 위임·BFF·팀 워크플로 경로를 생성기에 반영해 문서를 다시 만들었다. UI와 API 계약이 어긋나는지 보는 시험도 정리했다.
- **정리와 푸시**: 운영관리 플랫폼과 에이전트 저작 도구의 기능을 항목별로 대조한 문서를 쓰고, 푸시 전 보안 스캔을 거쳐 변경을 8개 묶음 커밋으로 나눠 올렸다.

## 에이전트 하네스

- **완료 게이트(Stop 훅)**: 에이전트가 "완료"라고 말하고 멈출 때 남은 일이 있는지 확인하는 게이트를 만들었다. 처음에는 응답의 마크다운을 해석했고, 해석기를 lexer 기반으로 교체했다가, 최종적으로 응답 끝의 명시 상태 줄(`상태: 완료` 또는 `상태: 미완료`)로 판정하는 방식으로 전환했다.

## 배운 점

- 완료 여부를 응답 문장에서 추론하면 파서를 아무리 고쳐도 예외가 남는다. 판정에 쓸 신호를 에이전트가 명시적으로 내게 하는 편이 단순하고 검증하기 쉽다.
- 외부 CLI로 긴 입력을 넘길 때는 표준 입력 파이프의 버퍼 한계를 먼저 의심해야 한다. 입력 크기가 커지는 시점에야 드러나는 종류의 버그다.
